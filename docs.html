Поток данных

1️⃣ Пользователь вводит email

Приложение валидирует формат email и отправляет запрос на backend.

2️⃣ Генерация и отправка кода

Backend генерирует 6-значный код и отправляет его на email пользователя.

3️⃣ Ввод кода подтверждения

Пользователь вводит полученный код в приложение.

4️⃣ Верификация кода

Backend проверяет код, его срок действия и количество попыток.

5️⃣ Сохранение данных

При успешной верификации данные сохраняются в localStorage браузера.

6️⃣ Доступ к приложению

Пользователь получает доступ к главной странице приложения.

🚀 Начало работы

Вариант 1: Быстрый старт (только фронтенд)

1. Откройте index.html в браузере 2. Введите email (например: sasaburk4659@gmail.com) 3. Нажмите "Далее" 4. Введите отправленный код подтверждения 5. Готово! Вы в главном меню

Вариант 2: С backend сервером

# Установка зависимостей pip install -r requirements.txt # Запуск сервера python server.py # Откройте http://localhost:8000/tg-mini-app/index.html

Вариант 3: Интеграция с Telegram

1. Создайте бота в @BotFather 2. Получите токен бота 3. Настройте Menu Button с URL приложения 4. Откройте приложение в Telegram
💡 Совет: Для production используйте HTTPS и настройте отправку кодов через SendGrid, AWS SES или другой email сервис.

📚 API Документация

POST /api/send-code

Отправить код подтверждения на email

Request: { "email": "user@example.com" } Response: { "success": true, "message": "Verification code sent to user@example.com", "demo_code": "123456" }

POST /api/verify-code

Проверить код подтверждения

Request: { "email": "user@example.com", "code": "123456" } Response: { "success": true, "message": "Code verified", "email": "user@example.com", "verified_at": "2026-03-01T08:00:00" }

GET /api/health

Проверка статуса сервера

Response: { "status": "ok", "timestamp": "2026-03-01T08:00:00", "service": "Telegram Mini App Backend" }

🔒 Безопасность

Реализованные меры безопасности

  • Коды подтверждения хранятся в зашифрованном виде в базе данных
  • Каждый код действует только 10 минут
  • Максимум 3 попытки ввода кода, затем блокировка
  • Коды можно использовать только один раз
  • Все данные пользователя хранятся локально в браузере
  • HTTPS рекомендуется для production окружения
  • Токен бота никогда не передается клиенту

Рекомендации для production

1. Используйте HTTPS для всех соединений 2. Установите переменные окружения для чувствительных данных 3. Используйте профессиональный email сервис (SendGrid, AWS SES) 4. Добавьте rate limiting для API endpoints 5. Логируйте все попытки авторизации 6. Регулярно обновляйте зависимости 7. Используйте Web Application Firewall (WAF) 8. Делайте резервные копии данных
